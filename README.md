# MyMinecraft

Paper 서버용 유틸리티 플러그인입니다. (대상: Paper 1.21.x, Java 21)

## 다운로드 / 설치

빌드할 필요 없이 [**Releases**](https://github.com/tntbbp123-wq/my-Minecraft/releases/latest) 페이지에서
바로 받을 수 있습니다. 릴리스마다 파일 3개가 첨부됩니다.

| 파일 | 용도 |
|---|---|
| `MyMinecraft-<버전>.jar` | **플러그인 본체.** 서버의 `plugins/` 폴더에 넣으세요 |
| `MyMinecraft-<버전>-sources.jar` | **소스 코드.** 코드를 확인하거나 IDE에 소스를 연결할 때 씁니다 |
| `MyMinecraft-ResourcePack.zip` | 리소스팩 (선택). 전용 아이템 텍스처용 — 아래 "리소스팩" 항목 참고 |

**설치 순서**

1. `MyMinecraft-<버전>.jar`를 서버의 `plugins/` 폴더에 넣습니다. 기존에 다른 버전의 jar가 남아
   있으면 반드시 지우거나 옮겨주세요 (두 개가 동시에 로드되면 충돌합니다).
2. 서버를 한 번 켰다 끄면 `plugins/MyMinecraft/config.yml`이 생성됩니다. 아래 "설정" 항목을 보고
   필요한 값을 조정한 뒤 다시 켜세요.
3. (선택) 아래 기능들은 다른 플러그인이 있어야 동작합니다. **없어도 나머지 기능은 정상 동작합니다.**

| 기능 | 필요한 플러그인 | 없을 때 |
|---|---|---|
| 전투모드(웅크리기+L), 소음 차단 포션의 소리 은폐 | [ProtocolLib](https://www.spigotmc.org/resources/protocollib.1997/) | 해당 기능만 비활성화 |
| 레바테인 3D 모델 | [BetterModel](https://github.com/toxicity188/BetterModel) 2.2.0 (Java 21 호환 버전) | 모델만 표시 안 됨 |
| AI 뉴스 자동 생성 | Google Gemini API 키 (무료) | `AI:` 없이 직접 쓴 뉴스만 사용 |
| 디스코드 침입 알림 | 디스코드 봇 토큰 | 해당 기능만 비활성화 |

> **업데이트할 때 주의:** `config.yml`은 이미 파일이 있으면 새 항목이 자동으로 추가되지 않습니다.
> 새 버전에서 추가된 설정(예: `raid-boss`)이나 바뀐 기본값(예: `combat.tag-seconds`)을 쓰려면
> 서버의 `config.yml`을 직접 수정하거나, 백업 후 삭제하고 다시 생성시켜야 합니다.

## 코드 확인

소스를 직접 읽어보려면 위의 `-sources.jar`를 받거나, 이 저장소의
[`src/main/java`](src/main/java/com/tntbbp/myminecraft)를 보면 됩니다. 패키지 구성은 아래와 같습니다.

| 경로 | 역할 |
|---|---|
| `MyMinecraftPlugin.java` | 진입점. 매니저 생성과 명령어·리스너 등록이 전부 여기 모여 있습니다 |
| `manager/` | 상태와 로직, YAML 저장 담당 (경제·홈·주식·강화·팀 등) |
| `gui/` | GUI 화면과 각 GUI를 구분하는 전용 `InventoryHolder` |
| `listener/` | 이벤트 처리. `GUIListener`가 모든 GUI 클릭을 분기합니다 |
| `command/` | 명령어 실행부와 탭 자동완성 |
| `raid/` | 레이드 보스 공용 뼈대(`RaidBoss`)와 개별 보스 |
| `model/`, `util/` | 데이터 객체와 공용 헬퍼 |

특정 기능이 어디 있는지 찾을 때는 `manager/`에서 이름이 같은 파일을 먼저 보면 빠릅니다
(예: 강화 → `EnhanceManager`, 주식 → `StockManager`). 커스텀 아이템은 모두
`PersistentDataContainer` 태그로 식별하고 외형은 `CustomModelData`로 처리합니다.

## 기능

- `/텔레포트요청 <플레이어>`, `/텔레포트수락`, `/텔레포트거절` — 플레이어 간 텔레포트 요청
- `/홈` — 저장된 홈을 GUI로 보여주고 클릭 이동(좌클릭)/삭제(우클릭)
- `/홈설정 <이름>`, `/홈삭제 <이름>` — 홈 저장/삭제 (기본 최대 5개, `config.yml`에서 조정)
- `/엔더상자` — 어디서든 엔더상자 열기
- `/메뉴` — 메인 메뉴 GUI (스폰 / 엔더상자 / 주식 / 은행 / 랜덤 이동 / 대장간 강화)
- `/로비`, `/로비 설정` — 로비 이동 / 설정(관리자)
- `/스폰`, `/스폰 설정` — 스폰 이동 / 설정(관리자)
- `/랜덤이동` — 월드 스폰 기준 중심 500x500 지역을 제외한 랜덤 위치로 이동 (쿨다운 존재)
- `/은행` — 은행 GUI 바로 열기 (아래 "은행" 항목 참고)
- **팀 & 코어** — 팀 단위로 거점을 공유하는 시스템
  - `/팀생성 <팀이름> <팀장닉네임>` (관리자) — 새 팀을 만들고, 팀장에게 **코어 1개를 자동 지급**함
  - `/팀원추가 <팀이름> <플레이어>`, `/팀원삭제 <팀이름> <플레이어>`, `/팀삭제 <팀이름>` (관리자) — 팀원 구성 관리
    (팀원삭제로 팀장은 제외할 수 없음)
  - `/팀정보 [팀이름]` — 팀장/팀원/거점 설치 여부 확인 (이름 생략 시 자기 팀 정보)
  - **코어** — 신호기(Beacon)를 변형해 만든 아이템. 제작법(3x3): 네더별-드래곤의 숨결-네더별 /
    바다의 심장-유리-바다의 심장 / 철블럭-철블럭-철블럭. **바닥에 설치하면 실제 신호기 블록이
    되고, 그 위치가 설치한 사람이 속한 팀의 거점(홈)이 됨** (팀 소속이 아니면 설치 불가, 다시
    설치하면 거점 위치가 갱신됨). 우클릭하면 바닐라 신호기 GUI 대신 전용 **커스텀 GUI**가 열림
    - 메인 화면에서 포인트로 강화석/두루마리(4등급)/별가루를 바로 구매 가능
      (가격은 `config.yml`의 `core.shop.prices`에서 아이템별로 조정 가능)
    - **암시장** 버튼 — 일반 상점에서 구할 수 없는 암시장 아이템 8종(일괄약탈주문서/함정설치키트/
      화염병/연막탄/밀도나침반/발자국추적기/혈흔나침반/소음차단포션)을 포인트로 구매하는
      별도 메뉴로 진입
    - **직업 전직 및 초월** 버튼 — 일반 직업 계열의 1차/2차 전직과 상위 단계 승급을 담당할
      예정이나, **아직 자리표시자이며 별도의 직업 시스템이 설계되는 대로 추후 구현 예정**임
      (히든 직업은 코어 GUI가 아닌 별도 경로로 분리될 예정)
- PvP 전투 로그 방지 — 다른 플레이어를 공격하거나 공격받으면 45초(`config.yml`의
  `combat.tag-seconds`에서 조정 가능)간 "전투 중" 상태가 되어, 그동안 관리자를 제외한
  모든 명령어 사용이 막히고(홈/랜덤이동/텔레포트 등으로 도망 방지), 이 상태로 접속을
  종료하면 즉시 사망 처리됨
- **OP 면역** — 서버 OP 권한을 가진 플레이어는 이 플러그인이 거는 모든 부정적 효과에 영향받지
  않음. 레바테인의 지옥의 화상, 드라켄피어스의 감전, 암시장 함정(독+위더 디버프/TNT)·화염병·
  연막탄, 스타포스/드라켄피어스 방어관통으로 인한 피해 증가, 전투 로그로 인한 접속종료 시
  강제 사망까지 모두 해당됨 (일반 PvP 전투 데미지 자체는 그대로 적용됨 — 무적이 아니라 이
  플러그인이 추가하는 디버프성 효과만 면제)
- **전투모드 (스킬 슬롯)** — 웅크리기(쉬프트) + L키(도전과제 화면 열기)를 동시에 하면 진입/해제되는
  별도의 전투 스킬 모드. 진입하면 1~4번 슬롯의 원래 아이템은 저장해두고 스킬 아이템으로 임시
  교체되며(우클릭으로 발동, 드롭/이동 불가), 다시 웅크리기+L을 누르면 원래 아이템으로 복구됨.
  접속 종료나 사망 시에도 원래 아이템을 잃어버리지 않도록 자동 복구/치환됨. 위 PvP 전투 로그
  방지(자동 발동)와는 완전히 별개의 시스템. **스킬 4개의 실제 효과는 아직 자리표시자이며
  추후 결정되는 대로 구현 예정**임 (`config.yml`의 `combat-stance` 항목에서 아이콘/이름 조정
  가능). **[ProtocolLib](https://www.spigotmc.org/resources/protocollib.1997/)이 설치되어
  있어야 L키 입력을 감지할 수 있음** — softdepend라서 없으면 이 기능 전체가 비활성화되고
  나머지 기능에는 영향 없음
- 주식(모의 투자) — 메뉴에서 가상 종목을 내부 포인트로 매수/매도. **기본 제공 종목은 없으며,
  관리자가 `/주식종류추가`로 추가한 종목만 거래소에 나타남.** 가격은 **1시간마다** 갱신되며,
  서버를 껐다 켜도 마지막 가격과 갱신 스케줄이 그대로 유지됨 (`stockdata.yml`에 저장)
- `/주식종류추가 <이름> <최소값> <최대값> <변동단위> <업종>` — 관리자가 새 주식 종목을 직접 추가.
  **시작가는 항상 최소값**으로 설정됨 (예: `/주식종류추가 감자농장 50 500 10 감자 재배·유통 회사`
  → 가격이 50에서 시작해 50~500 사이에서 10 단위로 변동). 업종은 AI가 뉴스를 쓸 때
  참고하는 설명으로, 실제 회사가 하는 일에 맞는 뉴스거리를 만드는 데 쓰임
- `/주식지급 <종목명> <유저> <수량>` — 관리자가 대가(포인트 차감) 없이 플레이어에게 주식을 바로 지급
- `/뉴스작성 <종목명> <상승|하락> <변동폭%> <내용 또는 AI:주제>`,
  `/가짜뉴스작성 <종목명> <상승|하락> <변동폭%> <내용 또는 AI:주제>` — 관리자가 주식 관련
  뉴스를 예약 작성. **전체 공지가 아니라**, 작성 후 **1시간 뒤부터 주식 거래소 GUI에서 해당
  종목에 커서를 올리면(툴팁) 뉴스 내용이 보이기 시작**하고, **2시간 뒤**(작성 시점 기준)
  진짜 뉴스라면 실제로 해당 종목 가격에 반영됨. 가짜 뉴스는 똑같이 툴팁에 보이지만 가격에는
  영향을 주지 않아, 플레이어가 뉴스만 보고 무조건 따라가면 손해를 볼 수 있음
  (지연 시간은 `config.yml`의 `news.reveal-delay-seconds`/`news.apply-delay-seconds`에서 조정)
  - 내용 대신 `AI:주제`를 입력하면 Google Gemini API(무료)로 기사 본문을 자동 생성함
    (`config.yml`의 `ai` 항목 설정 필요, 아래 AI 설정 참고)
  - **`/뉴스작성 <종목명> AI:[주제]`**처럼 등락 방향/변동폭을 아예 생략하면, 관리자가 직접
    쓰지 않은 것으로 보고 AI가 해당 종목의 **업종에 맞는 뉴스 내용은 물론 등락 방향과
    변동폭(%)까지 전부 스스로 판단**해서 정함 (주제도 생략 가능 - AI가 업종에 맞는 사건을
    직접 창작함). 변동폭 범위는 `config.yml`의 `news.ai-min-magnitude-percent`/
    `news.ai-max-magnitude-percent`로 제한 가능 (기본 1~10%)
- `/관리자메뉴` — 위 관리자 명령어 사용법과 현재 종목/대기 중인 뉴스 현황을 보여주는 GUI.
  명령어 안내 항목은 클릭하면 채팅창에 해당 명령어가 자동으로 입력되고, **강화석/등급별
  두루마리/레바테인/화폐 동전 5종(1G~10000G)까지 플러그인이 만드는 모든 특수 아이템을
  아이콘 클릭만으로 관리자 본인 인벤토리에 바로 지급받을 수 있음**
  (좌클릭 1개, 쉬프트+좌클릭은 최대 스택)
- **은행** (`/은행` 또는 `/menu` → 은행) — 기본 재화 이름은 **G**(`config.yml`의
  `economy.currency-name`에서 변경 가능). 실물 화폐(동전, 1G/10G/100G/1000G/10000G)를
  개별 구매(G→동전)/판매(동전→G)할 수 있고(기존에는 주식 거래소에 있던 기능을 여기로 옮김),
  **전부입금**(인벤토리의 모든 동전을 한 번에 G로 환전)/**전부출금**(보유 G 전액을 큰 단위
  동전부터 채워서 환전, 가장 작은 동전 단위 미만 잔액은 G로 남음) 버튼도 있음. 동전은 일반
  아이템이라 플레이어 간에도 자유롭게 주고받거나 거래 가능 (`config.yml`의 `currency.coins`에서
  등급/가치 조정 가능)
- 대장간 강화 — 전용 아이템 **강화석**을 소모해 아이템을 강화. **0강~4강은 실패 없이 무조건
  성공**하며, **5강부터는 직전 단계 성공률에 0.8을 곱한 값**이 적용됨(매 단계 20%씩 감소) —
  0강 100% → 5강 80% → 10강 26.214% → 15강 8.590% → 20강 2.815% → 30강 0.302% (성공률 표기는
  소수점 셋째 자리까지, 계산값이 0.001%보다 낮아지면 0.001%로 고정. `config.yml`의
  `enhance.guaranteed-level`/`decay-multiplier`/`min-success-percent`에서 조정 가능).
  **필요 강화석 개수는 시도할 때마다 1개씩 증가**함 (0강→1강: 1개, 1강→2강: 2개, ... — 확률
  강화 두루마리는 등급과 무관하게 항상 1개만 소모). **강화 비용은 포인트가 아니라 실물 화폐
  (동전)로 인벤토리에서 직접 차감됨** — 보유한 동전을 큰 단위부터 소모하고, 필요한 금액보다
  많이 뜯긴 초과분은 포인트로 환급됨. 동전이 부족하면 강화를 시도할 수 없음 (`/은행`에서

  - **드라켄 라이트닝** (F키 발동, 재사용 대기 20초): 히드라의 머리가 덮치는 듯한 번개 창극을
    전방으로 사출. 적중한 대상 주변의 적에게 최대 3명까지 연쇄로 옮겨붙으며, 맞은 모든 대상에게
    **감전**(둔화 + 방어무시 지속피해) 디버프 부여
  - **드라코닉 메타모포시스** (Q키 발동, 재사용 대기 25초): 전방에 번개 폭발을 일으켜 범위 내
    적에게 피해+감전을 준 뒤, 무기가 쌍단검 형상으로 일시 변형(기본 7초). 변형 중에는 이동속도와
    공격속도가 대폭 상승함 (`config.yml`의 `draken-pierce` 항목에서 두 스킬의 세부 수치 모두
    조정 가능)
  - F키(기본 손 바꾸기)와 Q키(기본 아이템 버리기)를 각각 스킬 발동 키로 가로채 사용하므로,
    드라켄피어스를 들고 있는 동안에는 두 키의 원래 동작(손 바꾸기/아이템 버리기)이 대신 스킬
    발동으로 동작함

## 빌드

```
mvn clean package
```

빌드 결과물은 `target/MyMinecraft-<버전>.jar` 형태로 생성됩니다 (버전은 `pom.xml`의
`<version>`). 서버의 `plugins/` 폴더에 넣으면 됩니다. 코드 확인용 소스 jar
(`target/MyMinecraft-<버전>-sources.jar`)도 함께 만들어집니다.

### 릴리스 만들기

`pom.xml`의 `<version>`을 올려 커밋한 뒤 그 버전의 태그를 올리면, GitHub Actions
(`.github/workflows/release.yml`)가 자동으로 빌드해 릴리스를 만들고 jar / 소스 jar /
리소스팩을 첨부합니다.

```
git tag v1.1.21
git push origin v1.1.21
```

태그와 `pom.xml`의 버전이 다르면 워크플로가 일부러 실패하니, 버전을 먼저 올렸는지 확인하세요.
(태그 없이 Actions 탭에서 "Release" 워크플로를 수동 실행할 수도 있습니다.)

업데이트할 때마다 `pom.xml`의 `<version>`을 올려서 jar 파일 이름이 매번 달라지도록 합니다.
이렇게 하면 서버에 어느 버전이 적용되어 있는지, 새 jar로 제대로 교체됐는지 파일명만 보고
바로 확인할 수 있습니다. (기존에 같은 이름의 jar가 `plugins/` 폴더에 남아있으면 삭제하거나
백업 폴더로 옮겨주세요.)

버전 형식은 `MAJOR.MINOR.PATCH`입니다. 초기 개발 단계인 지금은 **`1.1.(기능 수)`**
형태로 운영합니다 — 앞자리 `1.1`은 고정하고, 마지막 자리는 플러그인에 들어있는 주요
기능(시스템) 개수를 나타냅니다. 새로운 기능/시스템이 하나 추가될 때만 1을 올리며,
버그 수정이나 수치 조정처럼 기존 기능을 다듬는 변경에는 올리지 않습니다. 시작 기준점은
홈/엔더상자/메뉴/tpa/로비/스폰/랜덤tp/팀&코어/전투로그방지/전투모드/주식/은행/관리자메뉴/
레바테인/드라켄피어스/강화/초월의제단/스타포스/암시장/OP면역/디스코드알림 등 주요 시스템
약 20개를 기준으로 `1.1.20`부터 시작합니다. 정식 마일스톤에 도달하면 그때 MAJOR/MINOR를
의미 있게 올리는 방식으로 전환할 예정입니다.

## 설정

`config.yml`에서 경제 시작 포인트, 홈 최대 개수, tpa 타임아웃, 랜덤tp 반경/제외 크기/쿨다운,
주식 종목 목록 및 변동성, 강화 재료/성공확률/비용 등을 조정할 수 있습니다.

관리자 권한(`myminecraft.admin`, 기본 op)이 있는 플레이어만 `/스폰 설정`, `/로비 설정`,
`/특수아이템소환`, `/주식종류추가`, `/주식지급`, `/뉴스작성`, `/가짜뉴스작성`, `/관리자메뉴`를
사용할 수 있습니다.

## AI 뉴스 생성 설정 (선택 사항)

`/뉴스작성`, `/가짜뉴스작성`의 내용 자리에 `AI:주제`를 입력하면 AI가 기사를 자동으로 써줍니다.
이 기능은 **Google Gemini API**(무료 티어)를 사용하도록 구현되어 있습니다.

- [Google AI Studio](https://aistudio.google.com/)에 접속해 로그인 후 API 키를 무료로 발급받습니다
  (신용카드 등록 불필요).
- `config.yml`을 아래처럼 설정합니다.

```yaml
ai:
  enabled: true
  provider: "gemini"
  api-key: "여기에_발급받은_키_입력"
  model: "gemini-2.5-flash"
```

Gemini 2.5 Flash 기준 하루 약 1,500회 무료 요청이 제공되어, 서버 이벤트용 짧은 뉴스 기사
생성 용도로는 충분합니다. 한국어 생성 품질도 우수합니다. (다른 서비스로는 Groq도 무료
티어로 Llama 계열 모델을 매우 빠르게 제공하지만, 이 플러그인은 REST 호출이 가장 간단한
Gemini 기준으로 구현했습니다. 필요하면 `GeminiNewsClient.java`를 참고해 다른 제공자로
바꿀 수 있습니다.) `ai.enabled`가 꺼져있거나 키가 비어있으면 AI 기능은 비활성화되고,
`AI:` 없이 직접 입력한 뉴스 내용만 사용됩니다.

## 리소스팩 (전용 아이템 커스텀 텍스처)

`resourcepack/` 폴더(및 루트의 `MyMinecraft-ResourcePack.zip`)는 강화석, 두루마리 4등급,
레바테인, 화폐 동전 5종, 강화 GUI의 레벨별 진행 표시 화살표(10종)가 전용 아트워크로 보이도록
만든 클라이언트 리소스팩입니다. `CustomModelData`로 동작하므로 리소스팩을 적용하지 않은
플레이어에게는 원래 아이콘(강화석→자수정 조각, 두루마리→종이, 레바테인→네더라이트 검,
동전→구리/철/금 주괴·다이아몬드·네더라이트 주괴, 진행 표시→기본 화살표)으로만 보이고
기능에는 영향이 없습니다.

**적용 방법**

이 저장소가 **공개(public)** 상태라면, GitHub가 그대로 리소스팩을 호스팅해줍니다.
`server.properties`에 아래 두 값을 설정하세요.

```
resource-pack=https://raw.githubusercontent.com/tntbbp123-wq/my-Minecraft/main/MyMinecraft-ResourcePack.zip
resource-pack-sha1=18f75bbe719896532ad41eabd49c38cda01611ff
```

Minecraft 1.21.2 이후로는 아이템 텍스처 분기가 `assets/<ns>/models/item/*.json`의 `overrides`
방식에서 `assets/<ns>/items/*.json`의 `minecraft:range_dispatch` 방식으로 바뀌었습니다.
이 리소스팩은 두 방식을 모두 포함하고 있어서, 구버전(`overrides`)과 신버전(`items/*.json`)
클라이언트 모두에서 적용되도록 했습니다. (단, 1.21.4 이후의 정확한 스키마는 제가 확인할 수
없는 최신 버전이라 100% 보장은 못 드립니다 — 적용해보고 안 되면 알려주세요.)

`resource-pack-prompt`를 함께 쓴다면 반드시 JSON 형식이어야 합니다 (일반 텍스트를 그대로 넣으면
서버 시작 시 파싱 에러가 발생합니다):

```
resource-pack-prompt={"text":"이 서버는 필수 리소스팩이 있습니다. 다운로드 후 입장해주세요."}
```

해시는 `sha1sum MyMinecraft-ResourcePack.zip` 로 확인할 수 있습니다. 서버를 재시작하면
접속하는 플레이어에게 리소스팩 적용 여부를 묻는 창이 뜹니다.

## 전투 음악 (선택 사항)

PvP 전투 태그가 걸려 있는 동안 전투 음악을 재생할 수 있습니다. 소리가 **플레이어를 따라다니는
방식(비위치 재생)**이라 도망쳐도 끊기지 않고, 전투가 끝나거나 사망하면 즉시 멈춥니다.

**음원 파일은 이 저장소에 포함되어 있지 않습니다.** 음원마다 라이선스 조건이 다르고, 사용 허가가
곧 재배포 허가는 아니기 때문입니다. 서버 운영자가 직접 넣어야 합니다.

**넣는 방법**

1. 음원을 **OGG Vorbis**로 변환합니다. 마인크래프트는 MP3를 재생하지 못합니다.
   ```
   ffmpeg -i 원본.mp3 -vn -c:a libvorbis -q:a 3 -ar 44100 combat.ogg
   ```
2. 변환한 파일을 아래 경로에 넣습니다 (`sounds.json`은 이미 저장소에 있습니다).
   ```
   resourcepack/assets/myminecraft/sounds/music/combat.ogg
   ```
3. 리소스팩 zip을 다시 만들고 해시를 계산합니다.
   ```
   cd resourcepack && zip -r ../MyMinecraft-ResourcePack.zip . -x '.*' && cd ..
   sha1sum MyMinecraft-ResourcePack.zip
   ```
4. `server.properties`의 `resource-pack-sha1`을 새 해시로 갱신하고, zip을 플레이어가 받을 수 있는
   곳에 올립니다.
5. `config.yml`에서 기능을 켭니다. **트랙 길이를 실제 음원 길이(초)로 맞춰야** 긴 전투에서
   음악이 끊기지 않고 이어집니다.
   ```yaml
   combat:
     music:
       enabled: true
       track-length-seconds: 142   # 음원 길이에 맞추세요
       volume: 0.7
   ```

리소스팩을 적용하지 않은 플레이어에게는 **아무 소리도 나지 않을 뿐** 다른 영향은 없습니다.

> **음원 출처 표기**: 무료 음원도 대부분 출처 표기가 조건입니다. 사용하는 음원의 표기 문구를
> `resourcepack/CREDITS.txt`에 적어두세요. 또한 "사용 허가"와 "재배포 허가"는 다르므로,
> 음원이 든 리소스팩을 공개 배포하기 전에 라이선스를 다시 확인하시기 바랍니다.

## BetterModel 3D 모델 연동 (선택 사항)

레바테인을 손에 들면 [BetterModel](https://github.com/toxicity188/BetterModel)이
설치된 서버에서 3D 검 모델이 추가로 표시되도록 연동했습니다. (모델 파일 자체는
아직 이 저장소에 포함되어 있지 않습니다 — 확정되는 대로 `bettermodel-models/`에
추가될 예정입니다.)

> 참고: BetterModel에서 임의의 형태를 가진 고폴리곤 메쉬(mesh) 모델 지원은
> 3.0.0 버전부터 추가됐는데, 3.0.0 이상은 전부 Java 25 클래스 파일로 컴파일되어
> 있어 Java 21 서버에서는 로드되지 않습니다. Java 21 서버와 함께 쓰려면
> 큐브 조합(Blockbench cube) 모델만 지원하는 구버전(2.2.0)을 써야 합니다.
> 이 저장소의 `pom.xml`은 현재 2.2.0을 기준으로 컴파일됩니다.

**설치 방법**

1. BetterModel 플러그인 jar(Java 21과 호환되는 버전, 예: 2.2.0)를 서버 `plugins/`
   폴더에 넣고 서버를 재시작합니다.
2. `bettermodel-models/shadowflame.json`(또는 `config.yml`의
   `laevateinn.bettermodel-name`에 설정한 이름의 모델 파일)을 서버의
   `plugins/BetterModel/models/` 경로에 복사합니다.
3. 서버를 재시작(또는 BetterModel 리로드)하면 모델이 등록됩니다.

**동작 방식**

- MyMinecraft는 BetterModel을 `softdepend`로만 참조합니다. BetterModel이 설치되어
  있지 않으면 이 기능은 자동으로 꺼지고, 나머지 모든 기능(강화, 주식, 홈 등)은
  평소와 동일하게 작동합니다.
- BetterModel이 설치된 상태에서 플레이어가 메인핸드에 레바테인을 들면
  `config.yml`의 `laevateinn.bettermodel-name`(기본값 `shadowflame`)에 해당하는
  3D 모델이 플레이어에게 추가로 표시됩니다. 플레이어 본래 외형(스킨)은 그대로 유지되고,
  검 모델만 별도로 덧붙어 보입니다. 손에서 내려놓으면 자동으로 사라집니다.
- 모델 이름을 바꾸고 싶다면 `plugins/BetterModel/models/`에 다른 이름으로 모델을 넣고
  `config.yml`의 `laevateinn.bettermodel-name` 값을 그 이름으로 바꾸면 됩니다.

저장소가 비공개(private)라면 위 raw 링크는 서버가 접근할 수 없으니, zip을 직접
다른 곳(자체 웹호스팅 등)에 올리고 그 URL을 `resource-pack`에 넣어주세요.

리소스팩 zip 파일을 수정한 뒤에는 반드시 해시를 다시 계산해 `resource-pack-sha1`도
갱신해야 합니다. (zip 내용이 바뀌면 해시가 달라집니다.) 이 링크는 `main` 브랜치를
가리키므로, `main`에 반영되지 않은 변경사항(개발 브랜치에만 있는 커밋)은 이 URL에
아직 나타나지 않습니다.

## 디스코드 침입 알림 설정 (선택 사항)

암시장 아이템의 마지막 기능으로, 등록해둔 홈 근처에서 다른 플레이어가 활동하면 디스코드
개인 DM으로 알림을 받을 수 있습니다. 웹훅이 아니라 실제 디스코드 봇(JDA)을 통한 개인 DM
방식이라, 다음 설정이 필요합니다.

**서버 관리자가 한 번만 할 일**

1. [디스코드 개발자 포털](https://discord.com/developers/applications)에서 새
   애플리케이션을 만들고, "Bot" 탭에서 봇을 추가한 뒤 토큰을 발급받습니다.
2. "OAuth2 → URL Generator"에서 `bot` 스코프를 선택해 생성된 초대 링크로 봇을 자신의
   디스코드 서버에 초대합니다 (알림을 받을 플레이어들도 이 서버에 들어와 있어야 합니다 —
   디스코드는 서로 모르는 사용자 간의 DM을 막아두기 때문입니다).
3. `config.yml`의 `discord.bot-token`에 발급받은 토큰을 입력하고 서버를 재시작합니다.

**토큰 보관 방법 (선택)**

`discord.bot-token`은 평문 대신 아래 형식으로도 적을 수 있습니다.

| 형식 | 동작 | 비고 |
|---|---|---|
| `env:DISCORD_BOT_TOKEN` | 환경변수에서 읽음 | **가장 안전.** 값이 어느 파일에도 남지 않습니다 |
| `file:/경로/token.txt` | 지정한 파일에서 읽음 | config를 통째로 보여줘도 값은 노출되지 않습니다 |
| `enc:...` | `plugins/MyMinecraft/secret.key`로 복호화 | 평문을 적어둔 뒤 `/토큰암호화`를 실행하면 바꿀 값을 알려줍니다 |

> **`enc:`는 암호화지 보안이 아닙니다.** 플러그인이 재시작할 때마다 스스로 풀 수 있어야 하므로
> 복호화 키(`secret.key`)가 같은 서버 안에 있어야 하고, **서버 파일을 통째로 얻은 상대에게는
> 소용이 없습니다.** 설정 파일을 남에게 보여주거나 백업이 돌아다닐 때 눈에 띄지 않게 하는
> 용도이며, 확실히 감추려면 `env:`를 쓰세요.
>
> 같은 이유로 **토큰을 플러그인 jar 안에 넣어도 숨겨지지 않습니다.** 자바 바이트코드는 쉽게
> 역컴파일되고, 암호화해 넣더라도 복호화 키가 같은 jar 안에 있어야 하므로 함께 꺼낼 수 있습니다.
> 토큰은 배포물이 아니라 **서버를 운영하는 사람이 각자 자기 서버에만** 두는 값입니다.
> 저장소나 릴리스에 올라가는 파일에는 절대 넣지 마세요.

**서버 파일을 다른 사람도 볼 수 있다면**

호스팅 업체, 공동 운영자, 스태프처럼 서버 파일에 접근할 수 있는 사람으로부터 토큰을 기술적으로
숨기는 방법은 **없습니다.** 어떤 형식으로 저장하든 플러그인이 스스로 풀 수 있어야 하므로, 파일을
읽을 수 있는 사람은 결국 값도 얻을 수 있습니다. 그래서 "숨기기"가 아니라 **"새어나가도 피해가
작게"** 만드는 쪽으로 접근해야 합니다.

1. **봇 권한을 최소로 줍니다.** 이 플러그인은 개인 DM만 보내므로 디스코드 서버에서 어떤 역할
   권한도 필요하지 않습니다. 초대할 때 `bot` 스코프만 주고, 관리자·메시지 관리·멤버 관리 같은
   권한은 **전부 끄세요.** 그러면 토큰이 새어도 상대가 할 수 있는 건 "그 봇 이름으로 DM 보내기"
   정도로 제한됩니다.
2. **이 용도 전용 봇을 씁니다.** 다른 데 쓰는 봇과 토큰을 공유하지 마세요. 사고가 나도 이 기능만
   끄면 끝나도록.
3. **파일 권한을 좁힙니다.** 리눅스라면 서버 실행 계정만 읽을 수 있게 합니다.
   ```
   chmod 600 plugins/MyMinecraft/config.yml plugins/MyMinecraft/secret.key
   ```
   같은 서버에 있는 다른 사용자 계정은 막아주지만, root와 호스팅 업체는 여전히 볼 수 있습니다.
4. **유출되면 바로 재발급합니다.** 디스코드 개발자 포털 → 해당 앱 → Bot → **Reset Token**.
   기존 토큰은 즉시 무효화되고, 새 토큰을 `config.yml`에 넣고 서버를 재시작하면 됩니다.
   토큰 유출은 "막는 것"보다 **"빨리 갈아끼우는 것"**이 현실적인 대응입니다.

**플레이어가 할 일**

1. `/디스코드연동 <자신의 디스코드 사용자 ID>` — 자신의 디스코드 사용자 ID는 디스코드
   설정에서 "개발자 모드"를 켠 뒤 자기 프로필을 우클릭 → "ID 복사"로 확인할 수 있습니다.
2. 봇이 보낸 인증 코드를 DM으로 받은 뒤, `/디스코드연동확인 <코드>`로 연동을 완료합니다.
3. `/홈설정 <이름>`으로 알림받고 싶은 위치를 홈으로 등록해두면, 그 위치 근처(기본 30블록)에서
   다른 플레이어가 블록을 부수거나 상자류를 열 때마다 디스코드 DM으로 알림이 옵니다
   (`config.yml`의 `discord.alert-radius` / `alert-cooldown-seconds`에서 반경/간격 조정 가능).

`discord.bot-token`이 비어있으면 이 기능 전체가 자동으로 비활성화되고, `/디스코드연동`
명령어를 쓰면 "디스코드 봇이 설정되어 있지 않다"는 안내만 나오며 나머지 플러그인 기능에는
영향이 없습니다. (JDA 라이브러리를 통째로 jar에 포함해야 해서, 이 기능이 추가된 뒤로 빌드
결과물 jar 용량이 커졌습니다 — 정상입니다.)
